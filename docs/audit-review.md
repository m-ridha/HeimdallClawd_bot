# Audit assessment (16 October 2026)

The supplied audit is a useful static review, not a verified exploit report. Recommendations were checked against the project and pinned runtime. Tool availability and automatic execution remain priorities: the 55 policy grants, current auto-approval list, skill scripts and Open Skills synchronization are retained. This work is local and not deployed.

| Finding | Assessment / action |
| --- | --- |
| Named HTTP secrets | Confirmed: upstream resolved any alias for any allowed host. Added `http-secret-origins.patch`: github only at HTTPS api.github.com:443, agentmail only at HTTPS api.agentmail.to:443; userinfo, alternate ports/hosts and unknown aliases fail closed before resolution. Public HTTP without a named secret remains enabled. New aliases require an explicit origin-policy change and tests. |
| SSRF, redirects and rebinding | Existing upstream HTTP implementation disables redirects, validates resolved addresses and pins the connection to those addresses. No broad network restriction added. New integration checks confirm IPv6 ULA, loopback and named-secret misdirection are rejected without transport. Other tools have their own policies; this is not a claim that every external integration is audited. |
| Blanket approval changes | Not adopted. The owner requested autonomous tools with minimal limitations. Approval prompts would change that behavior. Untrusted-source prompt injection and mutating tools remain risks; precise credential routing is enforced instead of taking away the tools. |
| Executor memory and temporary files | Confirmed. Helpers now have a 96 MiB address-space limit per process and a private per-job TMPDIR/HOME cleaned when supervision ends. Shared /tmp remains usable for compatibility; programs that ignore TMPDIR can leave files outside per-job cleanup. This is not a process-tree RSS quota: forked processes and concurrent work can still exhaust container resources, and FSIZE remains a per-file limit. NPROC is shared by the helper UID. |
| Syscall compatibility | Confirmed omissions for timestamps, locks, allocator resizing and filesystem queries. Added utimensat, flock, mremap, statfs/fstatfs with touch/cp/tar and allocation regressions. clone3 remains denied with ENOSYS via a stacked filter, allowing glibc fallback to filtered clone. A real pthread and raw clone3 denial check are part of the startup probe. kill/tgkill and unrestricted prctl are deliberately not granted: same-UID jobs must not gain a way to signal each other or change confinement. Native Linux validation is required. |
| Runtime environment | Partially valid. The bot needs provider/MCP credentials. A parent environment allowlist alone does not stop native children inheriting those required secrets. Existing skills installer, Codespaces commands and executor jobs already clear their environments. Additional native child-process confinement needs a separate tested change; no claim of fixing it here. |
| Legacy builder and provenance | Confirmed path bug and incomplete dashboard build. Removed the superseded cross-compilation helper and stale generated provenance/hash files. Release packaging still generates and verifies checksums in both upload contexts. |
| Clean-tree verifier | Confirmed false positive for tracked IaC. Allow only the three intentional IaC files, continue rejecting unexpected Railway state, and replace per-file history content inspection with git grep per commit. Added temporary-repository regression coverage. |
| Transfer MCP recovery | Confirmed. Malformed, invalid-UTF8 and oversized lines produce bounded parse errors; oversized lines are drained, and the next request can succeed. The input size bound remains. |
| Codespaces diagnostics | Confirmed capability gap. SSH commands now return structured, bounded stdout/stderr with CLI exit status and truncation flags, redacting the local GitHub token. Output is explicitly untrusted data. Nonzero CLI status does not establish whether the remote program actually ran; control-plane failures retain sanitized static errors. |
| Remote-skill test API mismatch | Not a defect: ToolOutput implements conversion from strings, and default output is also valid. The cited difference does not demonstrate a stale test. |
| CI, dependency policy, action pinning | Useful maintenance proposals; parked for a separate change rather than mixing a release-policy overhaul into tool fixes. Existing manual native validation and published-release deployment gates remain. |
| Documentation drift | Fixed heartbeat status, executor tool lists, release trigger description, generated-provenance guidance and port typo. Historical dated verification notes are retained as history. |
| Supervisor capability set / PID reuse | Worth a dedicated Linux design review. The supervisor needs identity transitions, group cleanup and per-job ownership changes. No speculative capability removal or altered cleanup order is made here. Pipe/exit-status unwraps were replaced by explicit errors. |
| Bootstrap test | Added an assertion that the target exec line exists before replacement, preventing silent accidental server execution. |
| Backup, storage monitoring, IaC public exposure | Operational follow-ups remain. Volumes are not backups; existing docs say so. No unverified backup entitlement, public endpoint or paid service is assumed. |
| Codespaces default permissions | Existing owner-selected sandbox behavior retained; repository/devcontainer trust remains important. No automatic permission-policy change is made from a document recommendation. |

## Validation boundary

Portable Rust/Python checks and pinned-runtime HTTP integration tests can run locally. Linux-only syscall, address-space, thread and cleanup behavior must pass the branch's native build workflow before merge. This audit does not authorize a deployment, a new release, provider calls or changes to Railway variables. No secrets or private conversation data are included in tests.
